# Получение доступа после Stripe Checkout

Статический экран на существующем адресе `https://siblife54-dot.github.io/nauli/`. Не создаёт платёж и не подтверждает оплату. Показывается только при наличии `session_id` или `plan` в query string. Обычный лендинг и его тарифы не изменены.

## Redirect URL для каждого тарифа

```text
https://siblife54-dot.github.io/nauli/?plan=temel&session_id={CHECKOUT_SESSION_ID}
https://siblife54-dot.github.io/nauli/?plan=yakin&session_id={CHECKOUT_SESSION_ID}
https://siblife54-dot.github.io/nauli/?plan=ozel&session_id={CHECKOUT_SESSION_ID}
```

В настройке перенаправления оставить `{CHECKOUT_SESSION_ID}` буквально: Stripe подставит ID Checkout Session. Это описано в [официальной документации Stripe](https://docs.stripe.com/payment-links/post-payment#change-confirmation-behavior). Для Checkout Session, создаваемой вашим сервером, это тот же шаблон адреса успешного возврата. Настройки Stripe, Payment Links и режим платежей этой реализацией не меняются. Сейчас используйте настройки тестового режима.

## Где задавать ботов

Единственная конфигурация: `assets/access-config.mjs`, объект `ACCESS_PLANS`:

| plan в URL | Название | Поле botUsername |
| --- | --- | --- |
| temel | NAULİ TEMEL PAKET | nauli_temel_paket_bot |
| yakin | NAULİ YAKIN TAKİP | null — вписать собственный username |
| ozel | NAULİ ÖZEL | null — вписать собственный username |

Для двух последних заменить `null` строкой с username нужного бота. Допускается начальный `@`, но не полный URL. Не менять `plan=yakin` на внутренний ID карточки `yakin-takip`. Ненастроенный или неверный username показывает сообщение о недоступной активации, без ссылки и без подмены другим ботом.

Конфигурация публичная. В ней нет и не должно быть токенов Telegram, API-ключей Stripe, приватных ссылок каналов или секретов BotHunter. После изменения конфигурации опубликовать её в том же репозитории.

## Обработка ID

- Принимаются только структурно корректные `cs_test_…` или `cs_live_…` с непустым остатком из `A–Z`, `a–z`, `0–9`, `_`, `-`.
- Удаляется только один начальный префикс `cs_test_` / `cs_live_`. Остаток передаётся без обрезки, изменения регистра или перекодирования.
- Длина остатка должна быть от 1 до 64 символов: [ограничения Telegram deep links](https://core.telegram.org/bots/features#deep-linking). Более длинный ID показывает понятное сообщение вместо неработающей ссылки. Для него frontend не создаёт сокращённый токен.
- `?session_id=cs_test_…` без `plan` совместим со старым тестом и выбирает `temel`.
- `cs_live_…` без явного корректного `plan` блокируется. Поддержка формата live не включает реальные платежи и не меняет настройки Stripe.
- Пустой/неизвестный `plan`, повторяющиеся `plan`/`session_id`, недопустимые символы и незаменённый шаблон Stripe показывают ошибку. Никакой пользовательский ввод не вставляется в HTML как разметка.
- Telegram открывается только по нажатию «Telegram'dan Erişim Al». Автоматического перехода или отправки сообщения боту нет.

## Граница ответственности с BotHunter

`plan` — только маршрутизация к боту, не доказательство покупки. Даже структурно правильный `session_id` может не существовать или не быть оплаченным. Экран прямо сообщает, что оплата и пакет будут проверены в Telegram-боте до выдачи доступа.

Каждый сценарий BotHunter должен на своей стороне проверить через Stripe API фактический статус оплаты и соответствие продукта/Price именно своему пакету, а затем выдать доступ только к своему закрытому каналу. Учесть повторное открытие ссылки и не выдавать доступ повторно на основании одного лишь `/start`.

PAYLOAD не содержит префикса режима. Текущий тестовый сценарий восстанавливает `cs_test_` перед переданным остатком и использует тестовую среду Stripe. Будущее включение реальных платежей и обработка `cs_live_` требуют отдельной настройки на стороне ботов. Секреты и проверка оплаты остаются вне GitHub Pages.

В браузере нет запросов к закрытым Stripe API, хранения ID в localStorage или логирования платежных данных. Внешняя ссылка имеет `referrerpolicy="no-referrer"`. Активация курсов, настройка сценариев/каналов и реальная тестовая оплата не эмулируются этим сайтом.

## Проверки и публикация

```text
node scripts/build-sections.mjs
node --test scripts/access.test.mjs scripts/reviews.test.mjs
```

Новый экран не требует сборки или серверных зависимостей; существующая генерация программы и тарифов сохраняется. Публикация — корень ветки `main` существующего репозитория.

Проверить на телефоне: успешную маршрутизацию `temel`, legacy URL без `plan`, ненастроенные `yakin`/`ozel`, границу 64/65 символов, ошибочные/пустые/дублирующиеся параметры, возврат на лендинг. Для сквозной проверки используйте настоящий ID завершённой тестовой Stripe Checkout Session и настроенный сценарий BotHunter; придуманный тестовый ID проверяет только интерфейс и построение ссылки.
